# 64x64 polygon screen

A screen chip for Brickadia that draws filled and stroked shapes onto a
64x64 screen panel, one colour output per pixel. A shape can be kept in a slot
and moved later without recomputing its points, follow a parent shape,
or be animated per tick from a single push.

It stands on its own; the tinylua CPU *can* drive it, through the
`cpu-screen-connector` bridge. `screen.brz` is the shippable artifact:
the chip and the screen panel in one file.

```
screen.ws       the chip, GENERATED by gen.py -- edit the generator, not this
gen.py          python -u extras/screen/gen.py [lanes]  (default 64)
build.py        python -u extras/screen/build.py  (screen.brz, panel included)
painttest.py    functional test: push shapes, read the pixel globals
showtest.py     showcase.lua end to end (no colours)
showtest2.py    showcase2.lua end to end (colours, editing, morph, ticks)
animtest.py     anim.lua end to end
```

## The interface

```
              shapePoints --|           |-- px0 .. px4095: color
              shapeColors --|           |
                pushShape --|___________|
            shapeWireMode --|           |
                  shapeId --|           |
            drawAllShapes --|screen chip|
           clearAllShapes --|           |
            shapePosition --|___________|
            shapeRotation --|           |
               shapeScale --|           |
            parentShapeId --|           |
               brightness --|           |
        addToShapeInTicks --|           |
```

`pushShape` latches a shape and `drawAllShapes` paints it. Nothing is
painted without a draw, so a frame is a push followed by a draw.

- `shapePoints` -- pixel-corner coordinates (`x1, y1, x2, y2, ...`), up
  to 16 points. A rect covering pixels 0..3 has corners 0 and 4.
- `shapeColors` -- one colour per point, optional. A shape with
  different colours per point fills as a gradient; with one colour it
  fills flat. Omit the array and every point is white.
- `shapeWireMode` -- false fills (the outline closes itself), true
  strokes a 2px polyline along consecutive pairs. Repeat the first
  point to close a wireframe. A single point strokes as a 2x2 dot.
- `shapeId` -- 0 paints the shape once; 1..8 keep it, so pushing new
  points to the same id edits that shape in place, and pushing zero
  points deletes it. Keeping a shape means the CPU sends its geometry
  once and then only moves it.
- `clearAllShapes` -- forgets every kept shape. The panel keeps showing
  the scene until the next draw, which blacks it.
- `shapePosition`, `shapeRotation`, `shapeScale`, `parentShapeId` --
  optional. A shape pushed with `parentShapeId` N follows slot N, so
  one push to a parent moves its children with it. Leave them unwired
  for the identity.
- `brightness` -- 1 to 100, a dimmer for the whole panel. Unwired means
  the default (35: the bricks glow, and full brightness washes every
  colour out).
- `addToShapeInTicks` -- see below.

Nothing expires and nothing needs refreshing: a shape stays on the
panel until a draw paints something else over it.

## Animating a shape

`addToShapeInTicks` turns a push into an animation. With it set to N,
every other staged input becomes a *change per tick*, applied again
each tick for N ticks -- so one push walks a shape across the panel and
the CPU is free until it lands.

The animation becomes visible on `drawAllShapes`, like everything
else, and a new push to the same shape always replaces an animation
still in flight. Pushing with it left at 0 (or unwired) is the plain
instant push.

```
outNumArr(100, -(1.0 + 30))     -- animate the staged shape over 30 ticks
outNumArr(100, -1.0)            -- instant, as before
```

See the connector's README for the array layout that carries it.

```
python -u extras/screen/painttest.py           # ~7 min
python -u extras/screen/animtest.py [ticks]
python -u extras/screen/showtest.py [ticks]

```
