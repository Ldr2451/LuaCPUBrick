# 64x64 rect-fill pixel screen

A screen chip for Brickadia: one color output per pixel, a rect painter
into a framebuffer, and a microbrick wall whose property changers are
wired 1:1 to those pixels. `screen.brz` is the shippable artifact --
chip and wall in one file -- and `anim.lua` is a program that drives it.

```
screen.brz              the shippable artifact: chip + wall, pixels wired
screen.ws               the chip, GENERATED by gen.py -- edit the generator
gen.py                  python -u extras/screen/gen.py [lanes]  (default 64)
build.py                chip-only build with the stock compiler
painttest.py            functional test: push rects, read the pixel globals
anim.lua                a spirograph driver for the tinylua chip
animtest.py             end-to-end: anim.lua's port stream drives the screen
compiler-wall.patch     the compiler fork diff that emits the wall
compiler-wall.rs        the new emit/wall.rs, reproduced whole
```

Brick color is save data, not a port, so each pixel is a microbrick
carrying a `Component_BrickPropertyChanger`.  The emitter only emits
chip logic, so the wall is a `--wall` post-pass in a small compiler
fork; the diff is on this branch and `build.py` builds the chip alone
without it.

## The interface

```
             pts --|           |-- px0 .. px4095: color
          shapeN --|  screen   |
       rectColor --|           |
       pushShape --|           |
       redrawAll --|           |
```

`pushShape` latches (color, point count), `redrawAll` paints the latched
polygon: one row per tick, the ports mirror the framebuffer every tick.
Points arrive on `pts` as pixel-corner coordinates (a rect covering
pixels 0..3 has corners 0 and 4), up to 16 of them, with `shapeN` as
the count; a fully off-screen polygon paints nothing.  The fill is a
row's hull, exact for a convex polygon -- rect, triangle, oval, thick
line, curve segment -- and a concave outline fills its hull, so the
driver decomposes one into convex pieces.  Colors persist until
rewritten, so a frame is a sequence of push-then-redraw pairs, and the
wall keeps the last color forever -- no keepalive, no expiry.  The last
push before a `redrawAll` wins, so a stale stage cannot fire.  A bare
`redrawAll` replays the last polygon.

`anim.lua` drives these inputs from the tinylua chip: `outNum1 ->
pushShape`, `outNum2 -> redrawAll`, and one `outNumArr` write carries
the shape's points (the colour rides a scalar output).

## Running the tests

```
python -u extras/screen/painttest.py           # the fill, 9 shapes, ~36s
python -u extras/screen/animtest.py [ticks]    # anim.lua end to end
```

`painttest` composes a whole frame from nine shapes in one run -- rect,
clipped rect, alpha, triangle, convex hull, oval, hairline, thick line,
full wall -- and diffs the wall against a model of the fill, so a
dropped span, a bad hull or an off-by-one row shows up as a pixel diff.
A load-time edge on an unwired stage paints nothing (a zero point array
is a degenerate shape), and a bare `redrawAll` replays the last
polygon.

## Tools

| script | what it does |
| --- | --- |
| `python -u extras/screen/gen.py [lanes]` | regenerate the chip; lanes is the paint-speed knob |
| `python -u extras/screen/build.py` | build the chip with the stock compiler |
| `wirescript compile extras/screen/screen.ws -o extras/screen/screen.brz --wall px:64x64` | build `screen.brz` with the wall (needs the fork) |
