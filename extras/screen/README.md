# 64x64 polygon screen

A screen chip for Brickadia: one color output per pixel, a polygon
filler and polyline stroker into a framebuffer, and a microbrick wall
whose property changers are wired 1:1 to those pixels. `screen.brz` is
the shippable artifact -- chip and wall in one file -- and `anim.lua`
is a program that drives it.

```
screen.brz              the shippable artifact: chip + wall, pixels wired
screen.ws               the chip, GENERATED by gen.py -- edit the generator
gen.py                  python -u extras/screen/gen.py [lanes]  (default 64)
build.py                chip-only build with the stock compiler
painttest.py            functional test: push shapes, read the pixel globals
anim.lua                a spirograph driver for the tinylua chip
animtest.py             end-to-end: anim.lua's port stream drives the screen
compiler-wall.patch     the compiler fork diff that emits the wall
compiler-wall.rs        the new emit/wall.rs, reproduced whole
```

Brick color is save data, not a port, so each pixel is a microbrick
carrying a `Component_BrickPropertyChanger`.  The emitter only emits
chip logic, so the wall is a `--wall` post-pass in a small compiler
fork; the diff is on this branch and `build.py` builds the chip alone
without it.

## The interface

```
             shapePoints --|           |-- px0 .. px4095: color
             shapeColor --|  screen   |
              pushShape --|           |
              wireMode --|           |
               shapeId --|           |
              redrawAll --|           |
              clearAll --|           |
```

`pushShape` latches a shape -- colour, fill-vs-stroke, and slot -- and
`redrawAll` paints it: one row per tick, the ports mirror the
framebuffer every tick.
Points arrive on `shapePoints` as pixel-corner coordinates (a rect covering
pixels 0..3 has corners 0 and 4), up to 16 of them; the count is the
array's length, so the driver sends exactly as many points as the shape
has.  `wireMode` low fills (the outline closes implicitly); high
strokes a 2px polyline along consecutive pairs with no wrap, so the
driver closes a wireframe by repeating the first point and leaves an
open curve open (butt caps; joins overlap in the same colour).  A
single point strokes as a 2x2 dot.  A fully off-screen shape paints
nothing.
`shapeId` 0 paints immediately and forgets; 1..8 retain the shape, and
every retained commit clears the wall and repaints all live slots in
order -- so pushing new points to an id edits it in place, and pushing
zero points deletes it.  `clearAll` forgets every slot and blacks the
wall in one 64-tick burst (pulse it like a push), so the CPU never has
to track what is live.  Colors persist until
rewritten, so a frame is a sequence of push-then-redraw pairs, and the
wall keeps the last color forever -- no keepalive, no expiry.  The last
push before a `redrawAll` wins, so a stale stage cannot fire.  A bare
`redrawAll` replays the last shape.

`anim.lua` drives these inputs from the tinylua chip: `outNum1 ->
pushShape`, `outNum2 -> redrawAll`, `outNumArr -> shapePoints`
(elements 1..32, short shapes repeat the last point) with the colour
at elements 33..36 wired to `shapeColor` (`wireMode` and `shapeId`
stay unwired: immediate fills).

## Running the tests

```
python -u extras/screen/painttest.py           # fills, strokes, retained, ~113s
python -u extras/screen/animtest.py [ticks]    # anim.lua end to end
```

`painttest` composes whole frames from fills in one run -- rect,
clipped rect, alpha, triangle, convex hull, oval, hairline, thick line,
full wall -- then a wireframe, an open curve and a dot, then four
retained commits (store, compose, edit in place, delete), and diffs the
wall against models of every fill, so a dropped span, a bad hull, a
torn stroke, a stale slot or an off-by-one row shows up as a pixel
diff.  A load-time edge on an unwired stage paints nothing (a zero
point array is a degenerate shape), a seeded array paints a correct
prefix through whichever walk arms first, and a bare `redrawAll`
replays the last shape.

## Tools

| script | what it does |
| --- | --- |
| `python -u extras/screen/gen.py [lanes]` | regenerate the chip; lanes is the paint-speed knob |
| `python -u extras/screen/build.py` | build the chip with the stock compiler |
| `wirescript compile extras/screen/screen.ws -o extras/screen/screen.brz --wall px:64x64` | build `screen.brz` with the wall (needs the fork) |
