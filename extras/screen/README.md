# 64x64 polygon screen

A screen chip for Brickadia: one color output per pixel, a polygon
filler and polyline stroker into a framebuffer, and a microbrick wall
whose property changers are wired 1:1 to those pixels. `screen.brz` is
the shippable artifact -- chip and wall in one file -- and `anim.lua`
and `showcase2.lua` are programs that drive it.

```
screen.brz              the shippable artifact: chip + wall, pixels wired
screen.ws               the chip, GENERATED by gen.py -- edit the generator
gen.py                  python -u extras/screen/gen.py [lanes]  (default 64)
build.py                chip-only build with the stock compiler
colormath.py            test support: channel-wise colour math for the sim
painttest.py            functional test: push shapes, read the pixel globals
anim.lua                a spirograph driver for the tinylua chip
animtest.py             end-to-end: anim.lua's port stream drives the screen
showcase.lua            every primitive, retained slots, clear (no colours)
showtest.py             end-to-end for showcase.lua
showcase2.lua           colours, editing, the morph, the deferred clear
showtest2.py            end-to-end for showcase2.lua
compiler-wall.patch     the compiler fork diff that emits the wall
compiler-wall.rs        the new emit/wall.rs, reproduced whole
```

Brick color is save data, not a port, so each pixel is a microbrick
carrying a `Component_BrickPropertyChanger`.  The emitter only emits
chip logic, so the wall is a `--wall` post-pass in a small compiler
fork; the diff is on this branch and `build.py` builds the chip alone
without it.

## The interface

```
              shapePoints --|           |-- px0 .. px4095: color
              shapeColors --|  screen   |
               pushShape --|           |
               shapeWireMode --|           |
                shapeId --|           |
                drawAllShapes --|           |
               clearAllShapes --|           |
               shapePosition --|           |
               shapeRotation --|           |
                  shapeScale --|           |
           parentShapeId --|           |
              brightness --|           |
```

`pushShape` latches a shape -- its per-point colours, fill-vs-stroke,
and slot -- and `drawAllShapes` paints it: two rows per tick, the ports
mirror the framebuffer every tick.  (The draw input is called
`drawAllShapes`, not `redrawAllShapes`: without it nothing is painted at all.)
Points arrive on `shapePoints` as pixel-corner coordinates (a rect
covering pixels 0..3 has corners 0 and 4), up to 16 of them; the count
is the array's length, so the driver sends exactly as many points as
the shape has.  `shapeWireMode` (default false) low fills (the outline
closes implicitly); high strokes a 2px polyline along consecutive
pairs with no wrap, so the driver closes a wireframe by repeating the
first point and leaves an open curve open (butt caps; joins overlap in
the same colour).  A single point strokes as a 2x2 dot.  A fully
off-screen shape paints nothing.

`shapeColors` is optional and per-point: one colour per point, white
where absent.  Fills and strokes interpolate by true scanline
interpolation -- each row's span takes the colours of its two
crossing edges (each lerped along its edge by the row), then lerps
across the span -- so a polygon whose points carry different colours
fills as a smooth gradient, and a flat colour list reproduces the old
single-colour behaviour exactly.  A shape may omit the colours
entirely (an empty array): every point defaults to white.

`shapeId` 0 paints immediately and forgets; 1..8 retain the shape, and
every retained commit clears the wall and repaints all live slots in
order -- so pushing new points (and new colours) to an id edits it in
place, and pushing zero points deletes it.  `clearAllShapes` only forgets
every slot: it does NOT touch the wall.  The next `drawAllShapes` runs a
64-tick black fill, so a driver can clear memory and compose the next
image before anything changes on screen (pulse `clearAllShapes` like a
push; nothing replays afterwards, since both live flags die with it).

`shapePosition`, `shapeRotation`, `shapeScale` and `parentShapeId` are all optional
(a direct driver can leave them unwired; the connector drives the
first three from the CPU's output string array and the fourth from
its second string output).  A push stages them with the shape, and a
retained slot stores them with it -- so the CPU sends base geometry
once and then moves, rotates or scales it without recomputing a
single point.  Before either arm runs, the staged points are
transformed once: shapeScale, rotate about the origin by `shapeRotation.z`
(radians), translate.  The staged transform is first composed
through every ancestor -- pushing a shape with `parentShapeId` N
attaches it to slot N, pushing it with 0 detaches it -- so one push
to a parent's slot moves, rotates or scales the whole object: every
child (and grandchild -- the walk is capped at 8 steps, the slot
count, so the deepest acyclic chain resolves, and a dead, missing or
out-of-range parent, or a cycle, resolves to identity above it)
follows.  Unwired vectors read zeroes: shapePosition/shapeRotation zero are the
identity, and shapeScale zeroes mean identity too.

`brightness` is a live user slider the connector never drives -- it
stays unwired in the shipped save.  It takes 1 to 100, capped both
ends; an unwired port reads 0.0, which means the 100 default.  Every
painted colour's RGB is scaled by it (alpha is untouched -- brightness
is not opacity), and it acts at once: its edge reruns the retained
recomposite without the black clear (nothing moved, so overwriting is
exact) and refreshes the last immediate shape, so the whole wall
follows with no push and no `drawAllShapes`.  A push staged when the pass
ends supersedes the immediate refresh (its `drawAllShapes` paints the new
shape instead); racing a refresh mid-burst tears it like any raced
burst -- pace twiddles like pushes.  The wall bricks are emissive
(`BMC_Glow`), so colours read as emitted light and the slider is a
dimmer for the whole wall.

`addToShapeInTicks` turns a push into a per-tick animation: when it
reads N (truncated, minimum 1 -- 0 and unwired mean instant, the
long-standing behavior), every other staged input is a *delta*,
added to the stored shape again each tick for N ticks.  Points add to
points (past the staged count the tail holds still), colours add
channel by channel (missing colours add nothing), position, rotation
and scale add to the stored transform; the parent link and the
fill/stroke mode apply instantly, since links and modes are discrete.
Only retained shapes animate (id 0 paints instantly as always); the
first push to a dead slot establishes it instantly, since there is no
base to add to.  A new push to the same slot always wins -- even mid-
flight, starting from the current values -- an instant push kills the
animation outright, and `clearAllShapes` forgets every animation with
its slots.  Nothing repaints by itself: like everything else, motion
becomes visible on `drawAllShapes` (a bare one recomposites while any
animation is dirty, so the CPU sends one pulse per frame instead of
full stages).  Time freezes while a pass paints, so fast deltas cannot
smear across a slow repaint.
Colors persist until rewritten, so a frame is a sequence of
push-then-draw pairs, and the wall keeps the last color forever -- no
keepalive, no expiry.  The last push before a `drawAllShapes` wins, so a
stale stage cannot fire.  A bare `drawAllShapes` replays the last shape.

`anim.lua` drives these inputs from the tinylua chip through the
`cpu-screen-connector` bridge: `outNum1 -> pushShape`,
`outNum2 -> drawAllShapes`, `outNumArr` carrying only the points the shape
needs from element 1 on, closed by a terminator whose magnitude is
the colour count (see the connector's README for the full layout).
`anim.lua` sends no colours at all -- the default white keeps that
driver's write budget minimal, which is its job; the colour feature
is demonstrated by `showcase2.lua`.

## Running the tests

```
python -u extras/screen/painttest.py           # fills, strokes, retained, colours, xf, ~230s
python -u extras/screen/animtest.py [ticks]    # anim.lua end to end (43 ticks/frame)
python -u extras/screen/showtest.py [ticks]    # showcase.lua end to end
python -u extras/screen/showtest2.py [ticks]   # showcase2.lua end to end
```

`painttest` composes whole frames from fills in one run -- rect,
clipped rect, alpha, triangle, convex hull, oval, hairline, thick
line, full wall -- then a per-point gradient rect (every pixel the
exact bilinear blend), a wireframe, an open curve, a dot and a
diagonal gradient stroke, then four retained commits (store, compose,
edit in place, delete), the brightness slider (dimmed RGB at 50 with
nothing staged after, full again when the slider returns to the
unwired default, alpha untouched all ways),
and five transform commits (a scaled+moved square, a rotated rect
edit, a child attached to slot 1, the parent moved again with the
child following, the child deleted) -- and diffs the wall against
models of every fill, colour and transform, so a dropped span, a bad
hull, a torn stroke, a stale slot, a wrong gradient, a miscomposed
parent or an off-by-one row shows up as a pixel diff.  A load-time
edge on an unwired stage paints nothing (a zero point array is a
degenerate shape), a seeded array paints a correct prefix through
whichever walk arms first, and a bare `drawAllShapes` replays the last
shape.

The sim's `Expr_Math` gates are float-only and coerce colour tuples
to 0.0, so `colormath.install()` (imported by every colour-checking
test) patches them at runtime to the documented channel-wise
LinearColor semantics.  The patch is test-side only: the repo's
`irrun/` simulator is shared, untouched infrastructure.

## Tools

| --- | --- |
| `python -u extras/screen/gen.py [lanes]` | regenerate the chip; lanes is the paint-speed knob |
| `python -u extras/screen/build.py` | build the chip with the stock compiler |
| `wirescript compile extras/screen/screen.ws -o extras/screen/screen.brz --wall px:64x64` | build `screen.brz` with the wall (needs the fork) |
